CCDC LINUX TOOLKIT - SCRIPT REFERENCE NOTES
===========================================

This file holds every teaching / instructional comment that was removed from
ccdc_master.sh when it was split into the toolkit, organized under the script
each one now belongs to, in the order they originally appeared. Original
comments are reproduced verbatim (marked "Original:"). Where the split added
new code, a short "Why it works this way" note follows so the scripts
themselves can stay comment-light.

If you are new to bash, start with "Bash syntax reference" below. If you need
to run something unattended, read "Non-interactive mode (ccdc.conf)".


## Bash syntax reference
-------------------------------------------------------------------------
Original (the primer from the top of ccdc_master.sh, applies to every script):

    LEARNING NOTES (bash syntax used below, if you need a refresher)
    -------------------------------------------------------------------
    #!/usr/bin/env bash   shebang, finds bash wherever it lives on this distro
    VAR=value / $VAR      variables
    func() { ... }        a function
    if [ a = b ]; then .. fi     a decision (mind the spaces inside [ ])
    for x in list; do .. done    loop over a list
    case $x in a) ..;; esac      menu-style branch
    array=(a b c)          a list.  "${array[@]}" = all items
    >  / >>                overwrite / append a file
    2>/dev/null             discard errors
    $(command)              run command, capture output
    command -v foo          "which foo", used to detect what's installed

Additional constructs the split toolkit uses:

    . file / source file        load another file's functions into this shell
    [ "${BASH_SOURCE[0]}" = "$0" ]   true only when the file is RUN, not sourced -
                                each script uses this so the orchestrator (and
                                07/09/10) can source it for its functions
                                without triggering its menu
    declare -A map=([k]=v)      associative array (bash 4+). "${!map[@]}" = keys
    ${var:-default}             value of var, or default if unset/empty
    ${!name}                    indirect: the value of the variable NAMED by $name
                                (ask() uses this to look up its CCDC_* answer)
    printf -v VAR '%s' "$x"     assign to a variable whose name is in a string
    [[ $x =~ regex ]]           regex match; groups land in ${BASH_REMATCH[n]}
    ${arr[@]+"${arr[@]}"}       expands an array safely even when it is empty
                                under `set -u` on older bash
    <(command)                  process substitution: command output as a file
    cat > file <<'EOF' ... EOF  heredoc; quoted 'EOF' = no $ expansion inside.
                                Unquoted EOF + \$ is how 10 writes the watchdog
                                with some values baked in and others left live.
    (( 8#644 & ~8#600 ))        arithmetic with octal literals (file modes)
    local x                     function-scoped variable
    return N / exit N           leave a function / leave the whole script

    # Known malware/C2/RAT/RMM-tool ports worth hunting for. This is a curated
    # subset of the most recognized names (Metasploit, Back Orifice, NetBus,
    # Cobalt Strike clones, Tor, common RMM abuse) plus a few nation-state /
    # "foreign" C2 ports, trimmed way down from huge reference lists like
    # mthcht/awesome-lists - we are NOT trying to block all of these in the
    # firewall (default-deny already covers that), this is for spotting them
    # if something is ALREADY listening that shouldn't be.
    # port -> "Name|Category|Note"

Original (normal_users):

    # UID range differs a bit by distro, but 1000-59999 catches real human accounts
    # almost everywhere (some distros like older RHEL start at 500 - handle that too)

Original (restart_service):

    # tries systemd unit names in a sensible order, falls back to sysvinit

Why it works this way (new in the split):

  * Root-home anchoring. CCDC_HOME defaults to <root's home>/ccdc, looked up
    from /etc/passwd, not "~". Under sudo, "~" may be the operator's home on
    some distros but /root under cron - the watchdog and the scripts would then
    write to different places. Override with CCDC_HOME.
  * script.log is APPENDED, never truncated. The original truncated it on
    every run; with 13 scripts that would erase the change record. Each run
    writes a "===== ... started =====" header so runs are easy to tell apart.
  * backup_file keeps backups/pristine/<path> (first copy ever, never
    overwritten) plus a timestamped copy every time. Re-running a script can
    no longer replace your only pre-competition backup with a hardened copy.
  * set_line now matches the key as a whole word (followed by space, "=" or
    end of line) and escapes regex/sed metacharacters, so "PASS_MIN_DAYS"
    can't clobber "PASS_MIN_LEN" and values containing & or / are safe.
  * sshd helpers. sshd uses the FIRST value it sees, and anything after a
    "Match" line only applies inside that Match block. Appending settings to
    the end of sshd_config (what a generic set_line does) can therefore put
    them inside a Match block - silently ignored, or a syntax error that stops
    sshd. _sshd_set_in rewrites the first occurrence outside Match blocks and
    inserts new keys before the first Match. When sshd_config Includes
    sshd_config.d/*.conf (Ubuntu 22.04+, where files like 50-cloud-init.conf
    would win), the same settings also go into 00-ccdc-hardening.conf, which
    sorts first. sshd_commit_change runs `sshd -t` and restores the previous
    config if it fails, so a bad edit never reaches a restart.
  * ask() reads its answer from a config variable in non-interactive mode
    (ask "question" CONFIG_VAR default). Interactive behavior is unchanged:
    "yes" (or "y") is yes, anything else is no.
  * readme_services caches its answers in state/readme_services.conf so 01,
    08, 09 and 10 agree even when run as separate scripts; you are asked
    whether to reuse saved answers.
  * load_users refuses to continue with an empty authorized list - otherwise
    every account would be "unauthorized".
  * bash 4+ is required (associative arrays). `set -u` is only enabled on bash
    4.4+, because older bash (CentOS 7 ships 4.2) treats an empty array as an
    unbound variable and would abort.
  * fw_signature prints the CCDC-managed firewall rules as text; 08/09 store a
    cksum of it and the watchdog compares, so it catches rules being EDITED,
    not just flushed.

    13b. ENUMERATION - comprehensive nmap scan, neatly formatted report
         Scans this host (and optionally others you give it) the way
         red team would, so you know what they'd see before they do.

Original (nmap flags):

    # -p-        every TCP port (not just the common 1000)
    # -sS        TCP SYN (half-open) scan - the standard, quieter TCP scan type
    # -sV        service/version detection
    # -O         OS fingerprinting (needs root, which we are)
    # -sC        default safe NSE scripts
    # --script vuln   NSE vulnerability-detection scripts, flags known CVEs
    # -T4        aggressive timing - faster, fine on a LAN/lab, noisier on prod
    # -oA        write normal/xml/grepable all at once for later parsing

    # -sU separately: UDP has no handshake, so it's much slower and is always
    # run as its own pass rather than combined with -sS on all 65535 ports.
    # Covers DNS/SNMP/TFTP/NetBIOS-type services the TCP pass alone misses,
    # and is a favorite spot for red team to hide things people forget to check.

Why it works this way:

  * The UDP pass always scanned --top-ports 100 but its file/heading said
    "top 50"; the file is now udp_top100.txt so the label matches.
  * map_critical_dependencies writes inventory/dependencies.txt: established
    connections grouped by process (who talks to whom), where authentication
    comes from (nsswitch, sssd, krb5, ldap, realm), and DB/backend connection
    strings found in web/app roots with credentials masked. That is the
    "Finding the Monkey" map from scored service to critical services.
  * accounts.txt snapshots logins, UID 0, admin groups, sudoers,
    authorized_keys and crontabs BEFORE anything changes them.
  * The nmap scan can run in the background (CCDC_NMAP_BACKGROUND=yes) so a
    long -p- --script vuln scan does not hold up the first 15 minutes.

Original (staging state):

    # username -> which service/account this is for (for the PCR csv)

Original (section headers):

    3. PASSWORD POLICY

    4. USER AUDITING (accounts, sudo/admin groups, UID 0 check)
       (the rogue/unauthorized-account half lives here; UID 0 and admin
        groups moved to 04_privilege_escalation.sh)

Original (password_policy):

    # remove empty-password allowances wherever pam auth config lives

Original (staging header):

    5. STAGE PASSWORD CHANGES -- DOES NOT APPLY THEM
       Queues new creds, writes the PCR CSV, and the script HANGS
       waiting for you to explicitly confirm before anything is pushed.

Original (gen_password):

    # readable-ish but strong: 4 random words-ish chunks + digits/symbol

    (Note: the generator was never word-based - it is 16 random characters
     from A-Za-z0-9@#%+=. It now re-rolls until all four classes are present,
     because about 3 in 10 purely random 16-character draws lack a symbol and
     would fail the pwquality ocredit=-1 rule set by password_policy.)

Original (write_pcr_csv):

    # writes the PCR-formatted CSV for orange team, then the script pauses

Why it works this way:

  * Staged passwords persist in staging/pending_passwords.csv (mode 600)
    instead of only in memory. The split makes "stage now, apply later in a
    separate invocation" the normal path, so the queue has to survive the
    script exiting. Applied batches are archived as staging/applied_<ts>.tsv.
  * The PCR CSV (pcr/pcr_password_changes_<ts>.csv) is created with umask
    077 and fields are CSV-quoted, so a typed password containing a comma
    or quote can't break the columns orange team reads.
  * Apply needs either an interactive "yes" or the --confirm-pcr-submitted
    command-line flag. That flag cannot be set from ccdc.conf on purpose:
    a config file sitting on disk must never be able to apply passwords.
  * --auto exits with code 10 when something was staged; the orchestrator
    uses that to pause (TTY) or halt (no TTY).
  * Locking = usermod -L -e 1: lock the password AND expire the account,
    because a password lock alone does not stop SSH-key logins. The exact
    undo command is written to script.log. Without usermod (BusyBox),
    passwd -l is used.
  * Your own account ($SUDO_USER) is never locked or staged - change your
    own password by hand once the PCR is through.

      (the code sets "guest ok = no"; it does not comment out the block)

Original (FTP):

    11c. FTP HARDENING (vsftpd or proftpd, whichever is present)

Original (DNS):

    11d. DNS HARDENING (BIND9/named)

    # disable recursion for anyone but localhost/your own network (stops it being
    # abused as an open resolver / amplification source), hide version string

Original (section header):

    11. SERVICES FROM THE README

Why it works this way:

  * Every service change is snapshotted (tar of the config) and validated.
    Apache: apachectl -t; Samba: testparm; DNS: named-checkconf; proftpd:
    proftpd -t; SSH: sshd -t. If validation fails, or the service does not
    come back as active within ~5 seconds of the restart, the snapshot is
    restored and the service restarted on the old config.
  * Apache "Indexes": the original turned "Options Indexes FollowSymLinks"
    into "Options -Indexes FollowSymLinks". Apache 2.4 rejects mixing
    +/- options with plain ones, so that broke configtest and the scored
    web service. The word is now removed (or +Indexes becomes -Indexes),
    and an "Options Indexes" line with nothing else becomes "Options None".
  * Debian's conf-enabled/security.conf is a symlink; it is resolved first
    so the real file in conf-available is edited.
  * vsftpd: chroot_local_user=YES makes vsftpd 3 refuse logins when the
    user's home is writable ("refusing to run with writable root"), so
    allow_writeable_chroot=YES is set with it. ssl_enable=YES is only set
    when rsa_cert_file points at a real file - without a certificate
    vsftpd won't start at all. RHEL's /etc/vsftpd/vsftpd.conf is handled.
    write_enable stays NO unless CCDC_FTP_WRITE_ENABLE=yes (check whether
    scoring uploads a file).
  * proftpd: the whole <Anonymous>...</Anonymous> block is commented out;
    commenting only the opening tag left an unmatched closing tag.
  * BIND is never restarted if named-checkconf fails (the original checked,
    then restarted anyway).
  * disable_unneeded_services stops + disables (never uninstalls) services
    the README says are not needed. sshd is never auto-disabled.
  * updates() never reboots: a kernel update only takes effect on reboot,
    and scored services may not come back.


## 02_execution.sh - Execution
-------------------------------------------------------------------------
Original (section header):

    13. BAD PACKAGES / TOOLING CLEANUP (attacker tooling, not media files)

Why it works this way:

  * Package names differ by distro (nmap-ncat on RHEL, gnu-netcat /
    openbsd-netcat on Arch, telnet-server / tftp-server on RHEL), so they
    were added. pkg_is_installed checks dpkg, rpm, pacman and apk; the
    original only checked dpkg and rpm.
  * SUID/SGID: enumeration.sh only LISTS them. 02 classifies each one:
    known-good (passwd, sudo, ping, ...), HIGH (shells, interpreters,
    editors, find, tar, etc. - anything GTFOBins can turn into a root shell
    when SUID) and REVIEW (everything else). HIGH ones are stripped by
    default; REVIEW ones only one at a time, interactively. Every change
    appends its undo command to state/perm_restore.sh.
  * world-writable dirs without the sticky bit let any user delete or replace
    anyone's files; +t fixes that without breaking writes. o-w on files is
    off by default because web apps sometimes depend on it.
  * noexec on /dev/shm,/tmp,/var/tmp only applies to separate mounts and
    only until reboot; some installers and apps need exec in /tmp.


## 03_persistence.sh - Persistence
-------------------------------------------------------------------------
Original (section header):

    14. BACKDOORS / CRON / STARTUP CHECK

Why it works this way:

  * The pattern scan looks for the shapes reverse shells and droppers take:
    /dev/tcp, nc -e, bash -i, mkfifo, socat exec, curl|sh, base64 -d,
    anything running out of /tmp, /dev/shm, /var/tmp, and LD_PRELOAD.
    It covers cron, rc.local, /etc/profile(.d), shell rc files in every home,
    systemd units, init.d, motd scripts and XDG autostart, and lists
    unit/cron files changed in the last CCDC_RECENT_DAYS days.
  * cron.allow / at.allow: when an allow file exists, only users listed in it
    can use crontab / at. Off by default because some scored app might
    rely on a user crontab - check the list it prints first.
  * sshd -T prints the EFFECTIVE configuration after all includes; Match
    blocks are listed separately because they can re-enable root login or
    passwords for one user or address.
  * Red team often sets chattr +i on authorized_keys so it can't be edited;
    quarantine clears +i/+a first, copies the file, then removes it.
  * AllowUsers always includes the operator and only existing users; the
    scoring engine's account must be listed or SSH checks fail.


## 04_privilege_escalation.sh - Privilege Escalation
-------------------------------------------------------------------------
Original (section headers):

    6. SUDOERS CLEANUP

    9. FILE PERMISSIONS

Original (from user_auditing; the UID 0 / admin-group half lives here):

    4. USER AUDITING (accounts, sudo/admin groups, UID 0 check)

Why it works this way:

  * The original deleted every line containing NOPASSWD. On cloud images
    ("ubuntu ALL=(ALL) NOPASSWD:ALL" in sudoers.d) that removes the user's
    only sudo grant. Now the NOPASSWD: tag is stripped and the grant stays,
    so the user needs a password instead of losing sudo.
  * If you have no usable password yourself, stripping NOPASSWD would lock
    you out of sudo - the script stops and tells you to run passwd first.
  * On visudo -c failure, BOTH /etc/sudoers and /etc/sudoers.d are restored;
    the original only restored /etc/sudoers, so a broken sudoers.d file left
    sudo broken.
  * /etc/shadow stays root:shadow on Debian-family systems, where
    unix_chkpwd (setgid shadow) needs to read it; root:root elsewhere.
    Permissions are only ever tightened - RHEL ships /etc/shadow as 000 and
    the original chmod 640 loosened it.
  * Root is only locked without asking when you came in through sudo. If you
    are logged in directly as root, locking root may cost you console/su.
  * The admin-group sweep also covers members of sudo/wheel/admin who are
    not on any list; you (SUDO_USER) are never removed.


## 05_defense_evasion_logging.sh - Defense Evasion
-------------------------------------------------------------------------
(No original comments - this script is new, minimal functionality.)

Why it works this way:

  * journald Storage=persistent keeps the journal across reboots and
    journald restarts; logrotate keeps 12 rotations so a forced rotation
    (logrotate -f) can't push evidence out quickly.
  * Empty auth.log / secure / wtmp / btmp files are flagged - wiping them is
    a common way to hide a login.
  * HISTFILE=/dev/null, unset HISTFILE, HISTSIZE=0, set +o history or a
    .bash_history symlink in any rc file = someone hiding their commands.
  * /etc/ld.so.preload loads a library into EVERY process - the classic
    userland rootkit hook. It normally does not exist.
  * The integrity baseline (state/integrity_baseline.sha256) covers identity
    files, sudoers, sshd config, PAM, cron, profile, systemd units,
    authorized_keys and key binaries (sshd, sudo, su, ps, ss, ls, find,
    bash ...). It also lists files in watched dirs so NEW cron.d / systemd /
    profile.d / sudoers.d files are caught. The watchdog checks it every
    2 minutes but only logs when the set of changes changes. Re-baseline
    (--run baseline) after any intentional change, or you'll keep seeing it.
  * auditd keys: ccdc_identity, ccdc_priv, ccdc_ssh, ccdc_persist,
    ccdc_preload, ccdc_recon (every whoami/id run). Search with
    `ausearch -k ccdc_recon -i`.


## 07_discovery.sh - Discovery
-------------------------------------------------------------------------
(Sources enumeration.sh for enumerate_nmap and hunt_local_ports - one home
per function. No other original comments.)

Why it works this way:

  * The IOC hunt reads /proc directly (works without procps and on BusyBox):
    exe and cwd symlinks show binaries running from temp dirs or deleted
    after launch ("(deleted)"); a UID between 1 and 999 running a shell or
    interpreter is a service account that has been popped (www-data bash).
  * "Expected" ports = 22, 111 + README-needed services + CCDC_EXPECTED_PORTS
    + any extra ingress ports; everything else listening is printed.
  * respond: SIGSTOP freezes a process without destroying it (contain);
    /proc/PID/exe can be copied even if the file was deleted from disk, so the
    binary is quarantined before kill -9 (eradicate).


## 08_lateral_movement.sh - Lateral Movement
-------------------------------------------------------------------------
Original (section header, firewall):

    7. INGRESS/EGRESS FIREWALL
       "The best performing teams implemented good firewall policies
       for both incoming AND outgoing traffic."
       Tries nftables, then iptables, then ufw/firewalld as a front-end.

    (Note: the code order is nftables -> ufw -> firewalld -> iptables.)

Original (write_firewall_reload_helper):

    # saved separately so the watchdog can re-run the exact same ruleset logic above

Original (section header):

    8. KERNEL / NETWORK HARDENING (sysctl)

Why it works this way:

  * The original reload helper was a copy of the whole menu script. Run from
    cron with no input it looped forever printing the menu, every two minutes.
    The helper is now generated: it restores the saved ruleset (state/
    firewall.nft, iptables.rules ...) without prompting. The saved nft file
    starts with "flush ruleset", so nft -f swaps rules atomically - there is
    no moment with no firewall.
  * Ingress and egress are separate nftables tables (inet ccdc / inet
    ccdc_egress). A packet has to get through every base chain on a hook,
    so the two halves combine to the original behavior but can be applied,
    re-run or reverted independently. 08 deletes every OTHER table (as the
    original's flush did) but leaves inet ccdc_egress alone.
  * README answers now open every needed service: the original nft branch
    opened 53 only OUTBOUND for a DNS server and never opened Samba (139/445,
    137/138 udp), so those scored services went dark. MySQL/PostgreSQL ports
    only open if you say other hosts must reach them.
  * Safety rails: TCP 22 is kept open if you are connected over SSH (even if
    the README says no ssh); forwarding stays allowed when the host forwards
    traffic or runs Docker/Podman/LXC/libvirt (FORWARD DROP / ip_forward=0
    cuts containers off); ufw/firewalld are stopped if another backend is in
    use, otherwise the two fight and the watchdog flaps.
  * Ping is allowed by default (CCDC_ALLOW_PING) because scoring engines
    often check ICMP; ICMPv6 neighbor discovery is allowed so IPv6 keeps
    working.
  * Dropped packets are logged (rate-limited) with prefixes CCDC-IN-DROP /
    CCDC-FWD-DROP: `journalctl -k | grep CCDC-` or `dmesg | grep CCDC-`.
  * After ANY manual firewall change run `08_lateral_movement.sh --run save`,
    or the watchdog will see a changed signature and restore the saved rules.


## 09_c2_and_exfil.sh - Command and Control + Exfiltration
-------------------------------------------------------------------------
Original (egress part of firewall_stuff):

    # egress: only let outbound hit normal web/dns/ntp by default - attackers love
    # exfil/C2 over random high ports and "allow all outbound" firewalls

Why it works this way:

  * The baseline is now identical on every backend: tcp 53/80/443 and udp
    53/123 (+ tcp 25/587 for a mail box). In the original the nft branch only
    allowed DNS out when the box was a DNS server - so package installs broke
    - and the iptables branch had no NTP.
  * Before applying, 09 lists live outbound connections to ports that are not
    on the allowlist - often a real dependency (web app -> DB on another box,
    LDAP/Kerberos to a domain controller). Allow real ones interactively or
    with CCDC_EXTRA_TCP_OUT / CCDC_EXTRA_UDP_OUT. Connections to
    malware-watchlist ports are never offered.
  * Connections that were already open keep working after lockdown because
    of the "established" rule. That includes a C2 session that was set up
    before you got there: run --run hunt and kill what it flags.
  * firewalld has no real egress filtering of its own, so 09 uses its direct
    rules (an OUTPUT chain) for ipv4 and ipv6.

## ccdc_orchestrator.sh - Orchestrator
-------------------------------------------------------------------------
Original (run_all header and step comments):

    RUN EVERYTHING

    # 0. see what red team would see, before touching anything
    # 1. know what you have
    # 2. back up configs before changing them
    # 3. patch what you can
    # 4. ingress/egress
    # 5. uptime/monitoring watchdog every 2 min

Original (menu header):

    MENU

Why it works this way:

  * Run order is a priority override, not numeric: enumeration first
    (you can't safely touch what you haven't seen), passwords second
    (default credentials are the biggest initial-access category), then
    01-05, 07-10. 99 is only reachable through menu option 19.
  * Menu options 1-20 are the original numbering; 21 opens any script's own
    menu (IOC hunt, integrity check, egress hunt, persistence scan...).
  * In --auto mode the only stop is the mandatory pause after passwords are
    staged. With a terminal it waits for Enter (read from /dev/tty). Without
    one - typical for SSH-without-tty or Ansible-style tooling - it prints
    the CSV path and exits 3; continue with --auto --from 01.
  * A failing step is recorded and the run continues; the summary shows each
    step's result and the exit code is 4 if anything failed.


## Non-interactive mode (ccdc.conf)
-------------------------------------------------------------------------
Every script and the orchestrator accept:

    --auto | --non-interactive | -y   no prompts
    --config FILE                     answers file
    --run ACTION                      one action (scripts only; see --list)
    --list / --help

Interactive mode is the default whenever --auto is not given and
CCDC_NONINTERACTIVE is not yes. In interactive mode the README answers and
user lists are still taken from config when present; every other question
is asked.

ccdc.conf format: KEY=value lines; whole-line # comments; optional single
or double quotes; CRLF line endings are fine. Only keys starting with CCDC_
or NEED_ are read. The file is parsed, never sourced, so it can't run
commands. An environment variable of the same name wins over the file.
Search order: $CCDC_CONF, ./ccdc.conf, <toolkit dir>/ccdc.conf,
/etc/ccdc/ccdc.conf. A documented example is ccdc.conf.example.

Defaults when a key is missing are the "safe for uptime" choice: anything
that could take down a scored service or lock a human out defaults to no;
things that only reduce attack surface with no realistic uptime cost
(stripping SUID from shells, locking empty-password and extra UID-0
accounts, removing netcat/telnet) default to yes.

Exit codes:
    0  success
    1  setup error (not root, bad config path, missing script)
    2  unknown --run action
    3  orchestrator: halted after password staging (no TTY); 05 --run check:
       integrity changes found
    4  orchestrator: one or more steps failed
    10 passwords.sh --auto: passwords staged + PCR CSV written, not applied

Users: users.txt + admin.txt (one name per line, # comments ok) next to the
scripts or in the current directory, or CCDC_USERS_FILE + CCDC_ADMINS_FILE,
or CCDC_AUTHORIZED_USERS / CCDC_ADMINS (space separated).
